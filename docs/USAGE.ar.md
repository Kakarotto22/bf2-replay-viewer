# bf2demo - دليل الاستخدام (العربية)

الأداة `bf2demo` تقرأ ملف إعادة لعبة Battlefield 2 (`.bf2demo`) وتعرض كل ما أعلنه السيرفر للاعبين أثناء التسجيل.
المتطلبات: Python 3.9 أو أحدث، ولا حاجة لتثبيت شيء. شغّلها من مجلد المشروع:

```
python -m bf2demo path\to\file.bf2demo [الخيارات]
```

بدون أي خيار تطبع **التقرير الكامل المقروء**. كل الأزمنة بصيغة `mm:ss` منذ بداية التسجيل
(اللعبة تعمل بسرعة 30 تيك في الثانية).

## 1. أريد أن أرى ... - أي أمر أستخدم

| أريد أن أرى | الأمر |
|---|---|
| كل شيء بشكل مقروء | `python -m bf2demo FILE` |
| أنواع البيانات الموجودة في الملف وكميتها | `--inventory` |
| بعض أجزاء التقرير فقط | `--report players,flags` (الأسماء: `--list-sections`) |
| قواعد السيرفر (الجولات، الزمن، التذاكر، المركبات ...) | `--report settings` |
| من لعب، النقاط، القتلات، الوفيات | `--scoreboard` (أو `--report players`) |
| سجل القتل والدخول والخروج والفرق والاستيلاء بالترتيب | `--feed` (و`--feed-verbose` يضيف دخول/خروج المركبات) |
| متى غيّر كل علم مالكه | `--report flags` |
| تذاكر الفريقين وكيف انتهت الجولة | `--report overview,teams` |
| الفرق: من انضم لأي فرقة ومتى، والدعوات | `--report squads` |
| UAV وصناديق الإمداد والمظلات والمدفعية | `--report commander` |
| المركبات: ما أُنشئ وما دُمّر وما ركبه اللاعبون | `--report vehicles` |
| الصواريخ والقنابل المُطلقة | `--report weapons` |
| أين ذهب كل جندي ومركبة | `--tracks` (ملخص) أو `--export-tracks out.csv` (كل موضع) |
| زوايا الأبراج والمراوح والأجنحة | `--export-parts out.csv` |
| كل حدث مفكوك | `--events` |
| الأعلام وأماكن المركبات ونقاط الظهور | `--map-info` |
| كل شيء لبرنامجك الخاص (JSON) | `--export-json out.json` (أضف `--json-tracks` و`--json-parts` و`--json-indent 2`) |
| إعادة بناء `GamePlayObjects.con` للسيرفر | `--export-con out.con` |
| الجسور والصناديق والبراميل القابلة للتحطم | `--export-static out.con` |

يمكن جمع عدة خيارات: `python -m bf2demo FILE --feed --scoreboard`.
لحفظ الناتج في ملف: `> report.txt` (في PowerShell: `| Out-File report.txt -Encoding utf8`).

## 2. أقسام التقرير

`overview` السيرفر والخريطة والمدة وجدول الجولة - `settings` قواعد السيرفر - `teams` التذاكر - `players` النتائج -
`flags` تغيّر مالك الأعلام مع الزمن - `vehicles` المركبات - `weapons` المقذوفات - `radio` نداءات الإسعاف والذخيرة والإصلاح والإنعاش والرصد لكل لاعب - `squads` الفرق والدعوات - `commander` الطائرات المسيّرة وصناديق الإمداد والمظلات والمدفعية - `timeline` أهم اللحظات - `events` عدد الأحداث.

مثال: `python -m bf2demo FILE --report overview,flags,timeline`

## 3. ما الذي يحتويه التسجيل وما الذي لا يحتويه

* **يحتوي:** اللاعبين (الاسم، الفريق، الفرقة، النقاط، القتلات، الوفيات، البنغ، الرتبة)، القتلات مع السلاح/المركبة، الأعلام
  ومالكيها، التذاكر، كل مركبة وجندي مع موضعه عبر الزمن، زوايا أجزاء المركبات، المقذوفات، مواضع ظهور الجنود،
  الفرق والأوامر والقائد والتصويت والأوسمة، تشغيل/إيقاف الصوت، إعدادات السيرفر وقائمة الخرائط.
* **لا يحتوي أبداً:** عناوين IP للاعبين (انظر أدناه)، بصمات CD-key، كلمات السر، مضلّع منطقة القتال، نصف قطر الاستيلاء
  وأزمنته، تأخير إعادة ظهور المركبات، نص الدردشة، المباني والتضاريس.

الفهرس الكامل في `DATA.md` (لإعادة توليده: `python scripts/build_data_doc.py > DATA.md`).

### لماذا لا توجد عناوين IP للاعبين؟

هذا طبيعي، حتى في الألعاب الأونلاين. في بروتوكول اللعبة لا يرسل السيرفر عنوان لاعب إلى اللاعبين الآخرين ولا إلى التسجيل:
رسالة "إنشاء لاعب" (`CreatePlayer`) تحمل فقط الاسم ورقم الخانة والفريق وعلامة (روبوت/بعيد) ومعرّفات - وقد تحققت من
ذلك في الباينري (بناء هذا الحدث وقراءته). وكل بت في التسجيلات مفكوك (100%)، فلا شيء مخفي في بيانات غير مقروءة.
عناوين اللاعبين لا يعرفها إلا السيرفر نفسه (في سجلاته).

## 4. إعادة بناء ملف خريطة (`--export-con`)

```
python -m bf2demo FILE --export-con GamePlayObjects.con
python -m bf2demo FILE --export-con GamePlayObjects.con --merge OTHER1.bf2demo --merge OTHER2.bf2demo
```

تسجيل واحد يُظهر نقطة ظهور فقط إذا ظهر جنديان في الموضع نفسه تماماً، ويُظهر موضع مركبة دقيقاً فقط إذا أُعيد ظهورها أثناء
التسجيل. الخيار `--merge` يضيف تسجيلات أخرى لـ**نفس الخريطة** كدليل (قِيس على 92 تسجيلاً حقيقياً، انظر أدناه).
ملاحظات نهاية الملف تذكر ما رُصد وما نُسخ من الخريطة الأصلية. خيارات مفيدة: `--placeholder-spawn-points`
و`--drop-unobserved` و`--layout REF.con` و`--no-layout`.

## 5. JSON للبرامج

`--export-json out.json` يكتب الصيغة `bf2demo-json/2`: `demo` و`server_settings` و`map_info` و`players` و`feed` و`scoreboard`
و`tickets` و`control_points` و`objects` (و`tracks` مع `--json-tracks`). تغييرات أسماء الحقول عن الصيغة 1 مذكورة في `README.md`.

## 6. الاستخدام من Python

```python
from bf2demo.reader import load_demo
from bf2demo.replay import build_replay

replay = build_replay(load_demo("file.bf2demo"))
print(replay.server_info["time_limit"], [p.name for p in replay.player_history])
for tick, event in replay.events:
    if event.name == "KilledBy":
        print(tick / 30, event.fields)
```

## 7. نصائح

* ظهور `undecodable=0` في الأسطر الأولى يعني أن الملف كله مفهوم.
* التسجيل الذي بدأ في منتصف الجولة (وليس من تحميل الخريطة) عدّاداته دقيقة لكن بعض بياناته لقطة لحظية (انظر `DATA.md`).
* الاختبارات: `python -m unittest discover -s tests -t .`

## 8. قياس فائدة `--merge` (تسجيلات BF2RANGERS ليومين)

نقاط الظهور المكتشفة (جنديان في الموضع نفسه تماماً)، أفضل تسجيل منفرد ← كل تسجيلات الخريطة مدموجة. "مطابقة" = النقطة موجودة في ملف الخريطة الأصلي:

| الخريطة | عدد التسجيلات | منفرد | مدموج | المطابقة (بعد الدمج) |
|---|---|---|---|---|
| road_to_jalalabad | 3 | 15 | 21 | 21 من 21 |
| wake_island_2007 | 3 | 14 | 17 | 17 من 17 |
| gulf_of_oman | 4 | 28 | 35 | 22 من 35 |
| zatar_wetlands (مخصصة) | 4 | 34 | 40 | 0 (الخريطة المخصصة نقلت الأعلام) |

زيادة التسجيلات لنفس الخريطة تضيف نقاطاً ولا تحذف نقطة ولا تغيّرها. في خريطة Zatar المخصصة أعطى التسجيل المنفرد 4 نقاط مرصودة، ودمج خمسة تسجيلات أعطى 40.

## 9. الراديو والدردشة
نداءات الراديو تصل إلى التسجيل كأحداث HUD: الأمر `--report radio` (أو `--feed-verbose`) يعرض نداءات الإسعاف والذخيرة والإصلاح والإنعاش
والإنعاش التلقائي والوحدات المرصودة لكل لاعب. حدث `RadioMessage` المنفصل ونص الدردشة لم يظهرا في أي من التسجيلات التي فحصتها (92 تسجيلاً ليومين، 32 منها بلاعبين حقيقيين، إضافة للعينات القديمة)؛
وفي باينري السيرفر تُرسَل الدردشة كرسالة نصية على الاتصال لا كأحد الأحداث الـ63 التي يحفظها المسجِّل.

## 10. نهاية الجولة
المسجِّل يتوقف عند نهاية الجولة، فحدث `EndOfRound` لا يُحفظ أبداً. سطر `Ending` في التقرير يستنتج النهاية: حين يتوقف التسجيل وأحد الفريقين
عنده 30 تذكرة أو أقل ومتناقصة، يعرض تذاكر الفريقين وعدد الأعلام التي يملكها الفريق الآخر (مثال: Wake Island بتاريخ 2026-10-13 22:48،
فريق CH عند 5 تذاكر وUS يملك 6 من 6 أعلام).
